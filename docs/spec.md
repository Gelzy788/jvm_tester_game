# ТЗ: jquiz — CLI-тренажёр по Java Core с монетками (MVP, v2)

## 1. Цель

Консольная программа для подготовки к собеседованию junior Java-разработчика. Она тестирует знание Java Core в коротких сессиях (1–5 минут), начисляет монетки за правильные ответы и чаще показывает вопросы, на которых пользователь ошибался или которые давно не видел. Монетки тратятся во внутреннем магазине.

Целевой сценарий: пользователь запускает `jquiz`, отвечает на несколько вопросов и закрывает программу. Прогресс сохраняется автоматически после каждого ответа.

## 2. Технические рамки

- Язык: Python 3.10+.
- Только стандартная библиотека. Для тестов допускается `pytest` (dev-зависимость).
- Никаких внешних сервисов и сети: всё хранится локально.
- Поддерживаемые терминалы: Linux, macOS, Windows Terminal. На Windows программа при старте переключает stdin/stdout на UTF-8 (`sys.stdout.reconfigure(encoding="utf-8")` и аналогично для stdin) и включает обработку ANSI-последовательностей без внешних зависимостей.
- Установка: `pyproject.toml` с console-script `jquiz`, установка через `pipx install .` или `pip install -e .`. Запуск также возможен через `python -m jquiz`.
- Встроенный банк вопросов поставляется как package data и читается через `importlib.resources`.
- Всё время в программе берётся через внедряемый источник часов, а весь случайный выбор через внедряемый `random.Random`. Это нужно для тестов (см. раздел 15).

## 3. Входит в MVP

1. Банк вопросов из JSON-файла с валидацией.
2. Четыре типа вопросов: выбор варианта, короткий ответ, «что выведет код», открытый вопрос с самооценкой.
3. Игровая сессия из N вопросов с фильтром по теме и режимом «слабые места».
4. Выбор вопросов по весу ошибок и давности последнего показа.
5. Монетки, стрик правильных ответов, ежедневный бонус.
6. Магазин: расходники, титулы, пользовательские награды.
7. Статистика и список слабых тем и вопросов.
8. Автосохранение прогресса в локальный файл.

## 4. Не входит в MVP

- Интерактивное главное меню. Работа идёт только через подкоманды.
- Цветовые темы оформления.
- Мини-игры и любые заглушки для них.
- Проверка написанного кода через `jshell`/`javac`.
- Мультиплеер, таблицы рекордов, синхронизация между устройствами.
- Полноэкранный TUI (curses и аналоги). Ввод-вывод построчный.

## 5. Команды CLI

| Команда | Описание |
|---|---|
| `jquiz` | То же, что `jquiz play` |
| `jquiz play` | Сессия из 10 вопросов по всем темам |
| `jquiz play -n 5` | Сессия из 5 вопросов. Допустимо 1–50 |
| `jquiz play -t collections` | Сессия только по одной теме |
| `jquiz play --weak` | Сессия только из «слабых» вопросов (вес > 2.0) |
| `jquiz stats` | Статистика |
| `jquiz shop` | Показать каталог магазина, баланс и инвентарь |
| `jquiz buy <item_id>` | Купить товар |
| `jquiz title <title_id>` | Сделать купленный титул активным |
| `jquiz title off` | Убрать активный титул |
| `jquiz validate [path]` | Проверить банк вопросов и вывести отчёт |
| `jquiz reset` | Сбросить прогресс (с подтверждением) |
| `jquiz help` | Справка по командам |

Флаги `-n`, `-t` и `--weak` можно сочетать: `jquiz play -t streams --weak -n 3`.

Глобальные флаги для любой команды: `--no-color` (отключить цвета; то же делает непустая переменная окружения `NO_COLOR`) и `--ascii` (заменить эмодзи и спецсимволы на ASCII, см. 13.3).

Правила обработки аргументов:

- Неизвестная тема в `-t`: ошибка, вывод списка доступных тем, код выхода 2.
- `-n` вне диапазона 1–50: ошибка, код выхода 2.
- Если подходящих вопросов меньше N, сессия проводится по всем подходящим, а перед началом выводится сообщение «Доступно только K вопросов».
- Если подходящих вопросов нет (например, `--weak` без слабых вопросов), выводится понятное сообщение («Слабых мест пока нет») и программа завершается с кодом 0.
- `jquiz reset` требует ввести `да` или `yes`. Любой другой ввод отменяет сброс.

## 6. Банк вопросов

### 6.1. Источник

Если существует `~/.jquiz/questions.json`, используется он. Иначе используется встроенный банк из package data. Других источников нет.

### 6.2. Формат

Файл содержит JSON-массив объектов:

```json
[
  {
    "id": "col-001",
    "topic": "collections",
    "difficulty": 1,
    "type": "choice",
    "question": "Какая коллекция не допускает дубликатов?",
    "options": ["ArrayList", "LinkedList", "HashSet", "ArrayDeque"],
    "answer": 2,
    "explanation": "Set по контракту хранит только уникальные элементы."
  },
  {
    "id": "str-004",
    "topic": "strings",
    "difficulty": 2,
    "type": "short",
    "question": "Какой метод String возвращает строку без пробелов в начале и конце с учётом Unicode-пробелов?",
    "answer": ["strip", "String.strip"],
    "explanation": "strip() появился в Java 11 и, в отличие от trim(), учитывает Unicode-пробелы."
  },
  {
    "id": "out-010",
    "topic": "operators",
    "difficulty": 2,
    "type": "output",
    "question": "Что выведет код?",
    "code": "int i = 5;\nSystem.out.println(i++ + ++i);",
    "answer": ["12"],
    "explanation": "i++ вернёт 5 (i станет 6), затем ++i вернёт 7. 5 + 7 = 12."
  },
  {
    "id": "opn-003",
    "topic": "collections",
    "difficulty": 3,
    "type": "open",
    "question": "Как устроен HashMap внутри?",
    "answer": "Массив бакетов; индекс считается из hashCode() ключа...",
    "key_points": [
      "массив бакетов, индекс из hash",
      "коллизии: связный список, при 8+ элементах дерево",
      "load factor 0.75 и resize с удвоением"
    ]
  }
]
```

### 6.3. Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | string | да | Уникальный идентификатор |
| `topic` | string | да | Тема, формат `^[a-z0-9-]+$` |
| `difficulty` | int 1–3 | да | Сложность, влияет на награду |
| `type` | `choice` / `short` / `output` / `open` | да | Тип вопроса |
| `question` | string | да | Текст вопроса |
| `options` | string[] | только для `choice` | 2–6 уникальных непустых вариантов |
| `code` | string | только для `output` | Фрагмент кода, выводится отдельным блоком |
| `answer` | см. ниже | да | Правильный ответ |
| `key_points` | string[] | нет, только для `open` | Ключевые пункты эталонного ответа |
| `explanation` | string | да для `choice`/`short`/`output`, нет для `open` | Пояснение после ответа |

Формат `answer` по типам:

- `choice`: целое число, индекс правильного варианта в `options` (с нуля).
- `short`: непустой массив непустых строк, все допустимые ответы. Первый элемент считается каноническим, он показывается как правильный ответ и используется подсказкой «первая буква».
- `output`: непустой массив непустых строк без символа перевода строки. Первый элемент канонический.
- `open`: непустая строка, эталонный ответ (может быть многострочным).

### 6.4. Требования к содержанию стартового банка

- Темы: `oop`, `strings`, `collections`, `exceptions`, `generics`, `streams`, `multithreading`, `jvm-memory`, `operators`, `java-new-features`.
- Не менее 80 вопросов, не менее 6 на каждую тему, не менее 10 каждого типа.
- Вопросы `output` должны иметь однострочный детерминированный вывод в Java 17. Запрещены вопросы, вывод которых зависит от планировщика потоков, порядка итерации `HashMap`/`HashSet`, `hashCode()` объектов по умолчанию или версии JVM.
- Вопросы `short` должны допускать короткий однозначный ответ, а все разумные варианты записи должны быть перечислены в `answer`.
- Вопросы `open` формулируются так, как их задают на собеседовании junior-разработчику.
- Вопросы можно сгенерировать нейросетью, но каждый ответ должен быть проверен вручную.

### 6.5. Валидация

При загрузке банк проверяется по правилам из 6.3. Дополнительно проверяется уникальность `id` (при дубликате остаётся первый вопрос, остальные отбрасываются).

- Некорректный вопрос пропускается, в stderr выводится одна строка предупреждения с `id` (или порядковым номером, если `id` нет) и причиной.
- Если файл не является корректным JSON-массивом или после валидации не осталось ни одного вопроса, программа выводит ошибку и завершается с кодом 1.
- `jquiz validate [path]` проверяет указанный файл (по умолчанию тот, что выбран по 6.1), выводит все проблемы и сводку «валидно X из Y, по темам: …, по типам: …». Код выхода 0, если проблем нет, иначе 1.

## 7. Ход вопроса и проверка ответов

### 7.1. Служебные команды

Служебные команды начинаются с двоеточия, чтобы не конфликтовать с ответами:

| Ввод | Действие |
|---|---|
| `:h` | Использовать подсказку (см. 7.4) |
| `:s` | Пропустить вопрос расходником «Пропуск» |
| `:n` | «Не знаю» (недоступно для `open`, там используется оценка 3) |
| `:q` | Завершить сессию досрочно |

Если служебная команда недоступна (нет расходника, подсказка неприменима к типу, подсказка уже использована в этом вопросе), выводится причина, расходник не списывается и ввод запрашивается повторно.

### 7.2. Проверка по типам

**choice.** Варианты показываются в случайном порядке, правильный индекс пересчитывается. Пользователь вводит номер варианта (1…n). Ввод, который не является числом в этом диапазоне и не является служебной командой, приводит к повторному запросу и не считается ответом.

**short.** Пустой ввод приводит к повторному запросу. Ответ и каждый элемент `answer` нормализуются функцией `normalize_short`, ответ верен, если совпал хотя бы с одним. Шаги `normalize_short` по порядку: обрезать пробелы по краям; привести к нижнему регистру; заменить любые последовательности пробельных символов одним пробелом; удалить завершающие `;`; удалить завершающие `()`; снова обрезать пробелы.

**output.** Пустой ввод приводит к повторному запросу. Сравнение через `normalize_output`: обрезать пробелы по краям. Регистр и внутренние пробелы значимы.

**open.** Показывается вопрос и приглашение «Подумай или запиши ответ. Enter — показать эталон». Введённый текст никак не проверяется и не сохраняется. После Enter показываются эталонный ответ и `key_points` (если есть), затем запрашивается самооценка: `1` — знал, `2` — частично, `3` — не знал. Любой другой ввод приводит к повторному запросу. На этапе самооценки доступна только команда `:q`. На этапе до показа эталона доступны `:s` и `:q`.

### 7.3. Исходы вопроса

Каждый показанный вопрос заканчивается одним из исходов:

| Исход | Когда |
|---|---|
| `correct` | Верный ответ (`choice`/`short`/`output`) или оценка «знал» (`open`) |
| `partial` | Оценка «частично» (`open`) |
| `wrong` | Неверный ответ (`choice`/`short`/`output`) |
| `dont_know` | `:n` или оценка «не знал» (`open`) |
| `skipped` | `:s` |
| `aborted` | `:q` |

Эффекты исходов на вес, монетки, стрик и счётчики описаны в разделах 8 и 9 и сведены в таблицу 9.3.

После исхода `aborted` вопрос не учитывается нигде (ни вес, ни счётчики, ни `last_seen`), прогресс сохраняется, показывается итог сессии.

После исходов `correct`, `wrong`, `dont_know` для `choice`/`short`/`output` выводится: «Верно» (зелёным) или «Неверно» (красным), правильный ответ (для `choice` текст варианта, для остальных канонический), пояснение и начисленные монетки. Для `open` после самооценки выводятся начисленные монетки.

### 7.4. Подсказки

- **50/50** (`hint_5050`): применима только к `choice` с 4 и более вариантами. Убирает из показа неверные варианты так, что остаются правильный и один случайный неверный. Варианты перенумеровываются 1 и 2.
- **Первая буква** (`first_letter`): применима только к `short` и `output`. Показывает первый символ канонического ответа и длину канонического ответа.
- В одном вопросе можно использовать не больше одной подсказки.
- Подсказка не меняет награду за верный ответ.
- При нажатии `:h` используется применимая к типу подсказка. Если её нет в инвентаре или ни одна не применима, выводится причина.

## 8. Выбор вопросов

### 8.1. Вес

У каждого вопроса в прогрессе хранится `weight`. Вопрос без записи в прогрессе имеет вес `1.0`.

| Исход | Новый вес |
|---|---|
| `correct` | `max(weight * 0.6, 0.25)` |
| `partial` | без изменений |
| `wrong`, `dont_know` | `min(weight * 2, 16)` |
| `skipped` | без изменений |
| `aborted` | без изменений |

### 8.2. Давность

`last_seen` обновляется на текущее время при исходах `correct`, `partial`, `wrong`, `dont_know`, `skipped`. Множитель давности `recency`:

- вопрос ни разу не показывался: `2.0`;
- с `last_seen` прошло меньше 1 суток: `0.5`;
- иначе: `min(1 + days / 7, 3.0)`, где `days` — дробное число суток с `last_seen`.

### 8.3. Алгоритм

1. Сформировать пул: вопросы, подходящие под фильтр темы. В режиме `--weak` дополнительно оставить только вопросы с `weight > 2.0`.
2. Для каждого вопроса посчитать `score = weight * recency`.
3. Выбрать `min(N, размер пула)` вопросов взвешенным случайным выбором по `score` без возвращения: после каждого выбора вопрос удаляется из пула.
4. Вопросы задаются в порядке выбора. Внутри сессии вопрос не повторяется.

Вопросы выбираются один раз в начале сессии, изменения весов во время сессии на её состав не влияют.

### 8.4. Определения

- Слабый вопрос: `weight > 2.0`.
- Слабая тема: средний вес всех вопросов темы в текущем банке (непоказанные считаются с весом 1.0) больше `1.5`.

## 9. Экономика

### 9.1. Начисление

Базовая награда `base` = значение `difficulty` (1, 2 или 3).

| Событие | Монетки |
|---|---|
| `correct` | `base` |
| `correct` на слабый вопрос (вес до ответа > 2.0) | ещё +1 |
| `partial` | `base // 2` (для сложности 1 это 0) |
| Стрик достиг значения, кратного 5 | +5 |
| Ежедневный бонус | +10 один раз за календарный день, в момент 10-го засчитанного ответа |
| `wrong`, `dont_know`, `skipped` | 0 |

### 9.2. Стрик и дневной счётчик

- Стрик хранится в прогрессе и переживает перезапуск и конец сессии.
- `correct`: стрик +1, затем проверяется бонус за кратность 5, затем обновляется `best_streak`.
- `wrong`: стрик сбрасывается в 0.
- `partial`, `dont_know`, `skipped`, `aborted`: стрик не меняется.
- Дневной счётчик учитывает исходы `correct`, `partial`, `wrong`, `dont_know`. Если локальная дата не совпадает с `daily.date`, счётчик сбрасывается: `date` = сегодня, `answered` = 0, `bonus_claimed` = false.

### 9.3. Сводная таблица исходов

| Исход | Вес | `last_seen` | Монетки | Стрик | Счётчик вопроса | Дневной счётчик |
|---|---|---|---|---|---|---|
| `correct` | ×0.6 | да | `base` (+1 за слабый) | +1 | `correct` +1 | +1 |
| `partial` | — | да | `base // 2` | — | `partial` +1 | +1 |
| `wrong` | ×2 | да | 0 | сброс | `wrong` +1 | +1 |
| `dont_know` | ×2 | да | 0 | — | `dont_know` +1 | +1 |
| `skipped` | — | да | 0 | — | `skipped` +1 | — |
| `aborted` | — | — | 0 | — | — | — |

### 9.4. Магазин

Каталог (`item_id` используется в `jquiz buy`):

| item_id | Название | Цена | Тип | Условие |
|---|---|---|---|---|
| `hint_5050` | Подсказка 50/50 | 15 | расходник | — |
| `first_letter` | Подсказка «Первая буква» | 10 | расходник | — |
| `skip` | Пропуск вопроса | 20 | расходник | — |
| `title_junior` | Титул «Junior» | 50 | титул | — |
| `title_middle` | Титул «Middle» | 200 | титул | куплен `title_junior` |
| `title_senior` | Титул «Senior» | 500 | титул | куплен `title_middle` |
| `title_jvm_whisperer` | Титул «JVM Whisperer» | 1500 | титул | куплен `title_senior` |

Правила:

- Расходники копятся в инвентаре без лимита, одна покупка добавляет одну единицу.
- Титул покупается один раз. Повторная покупка отклоняется с сообщением.
- Купленный титул автоматически становится активным. Активный титул меняется через `jquiz title`.
- Если монеток не хватает, покупка отклоняется с сообщением, сколько не хватает. Если не выполнено условие, сообщается, какой титул нужен.
- Неизвестный `item_id` выдаёт ошибку и список доступных товаров, код выхода 2.

### 9.5. Пользовательские награды

В необязательном файле `~/.jquiz/config.json` пользователь описывает свои реальные награды:

```json
{
  "custom_rewards": [
    { "name": "Перерыв на кофе", "price": 100 },
    { "name": "Серия сериала", "price": 500 }
  ]
}
```

- Каждой награде присваивается `item_id` вида `reward-1`, `reward-2`… по порядку в файле.
- `name` — непустая строка, `price` — целое число больше 0. Некорректные записи пропускаются с предупреждением. Если файл повреждён, он игнорируется целиком с предупреждением.
- В `jquiz shop` награды выводятся отдельным разделом.
- Покупка награды списывает монетки и пишет запись в историю с полем `name`. Награды можно покупать сколько угодно раз.

## 10. Хранение прогресса

Файл `~/.jquiz/progress.json`. Каталог `~/.jquiz` и файл создаются при первой необходимости.

```json
{
  "version": 1,
  "coins": 137,
  "streak": 3,
  "best_streak": 14,

Требования:

- Время хранится в ISO 8601 с локальным смещением (`datetime.now().astimezone().isoformat(timespec="seconds")`). Дата в `daily` — локальная календарная дата.
- Сохранение происходит после каждого исхода, кроме `aborted`, после каждой покупки, смены титула и сброса.
- Запись атомарная: временный файл в той же директории, `flush` и `os.fsync`, затем `os.replace`.
- Отсутствующие поля заполняются значениями по умолчанию, лишние поля сохраняются как есть.
- `history` хранит последние 200 записей, более старые удаляются при записи.
- Если файл не читается как JSON или имеет неверную структуру, он переименовывается в `progress.json.bak.<YYYYMMDD-HHMMSS>`, программа сообщает об этом и начинает с чистого прогресса.
- Если `version` больше поддерживаемой, программа выводит ошибку и завершается с кодом 1, не изменяя файл.
- Записи о вопросах, отсутствующих в текущем банке, сохраняются в файле, но игнорируются в выборе и статистике. Это нужно, чтобы прогресс не терялся при временной смене банка.
- `jquiz reset` после подтверждения заменяет прогресс чистым, предварительно сохранив копию по тем же правилам, что и при повреждении.

## 11. Статистика

`jquiz stats` выводит:

- баланс монеток и активный титул;
- всего ответов (исходы `correct`, `partial`, `wrong`, `dont_know`), процент верных (`correct` от этого числа), число частичных;
- текущий и лучший стрик;
- инвентарь расходников;
- таблицу по темам: ответов, процент верных, средний вес, пометка «слабая» для слабых тем;
- топ-5 слабых вопросов по убыванию веса (при равенстве — по убыванию `wrong + dont_know`): `id`, тема, первые 40 символов текста, вес. Если слабых вопросов нет, вместо топа выводится «Слабых вопросов нет».

## 12. Сессия и итог

Шапка перед первым вопросом:

```
jquiz  ·  Middle  ·  137 🪙  ·  стрик 3
```

Если титула нет, он не выводится.

Пример вопроса `choice`:

```
[3/10] collections · ★★☆
Какая коллекция не допускает дубликатов?
  1) ArrayDeque
  2) HashSet
  3) ArrayList
  4) LinkedList
Ответ (:h подсказка, :s пропуск, :n не знаю, :q выход): 2

✔ Верно! +2 🪙
Set по контракту хранит только уникальные элементы.
```

Пример вопроса `open`:

```
[5/10] collections · ★★★ · открытый вопрос
Как устроен HashMap внутри?
Подумай или запиши ответ. Enter — показать эталон (:s пропуск, :q выход):

Эталон:
  Массив бакетов; индекс считается из hashCode() ключа...
Ключевые пункты:
  • массив бакетов, индекс из hash
  • коллизии: связный список, при 8+ элементах дерево
  • load factor 0.75 и resize с удвоением
Оцени себя (1 знал, 2 частично, 3 не знал): 2

◐ Частично. +1 🪙
```

Итог сессии (выводится и при досрочном выходе):

- верно / частично / неверно / не знаю / пропущено из показанных вопросов;
- заработано монеток за сессию и текущий баланс;
- лучший стрик в сессии;
- темы, где были исходы `wrong` или `dont_know`;
- блок «Разбор ошибок»: для каждого вопроса с исходом `wrong` или `dont_know` первые 60 символов вопроса и правильный ответ (для `open` не выводится, только тема и начало вопроса).

## 13. Требования к выводу

### 13.1. Цвета

ANSI-цвета: зелёный для верного, красный для неверного, жёлтый для частичного и предупреждений, приглушённый для пояснений. Отключаются флагом `--no-color` или переменной `NO_COLOR`. Также отключаются автоматически, если stdout не является терминалом.

### 13.2. Ширина и переносы

- Ширина строки: `min(80, ширина терминала)`.
- Обычный текст переносится по словам.
- Блок кода в `output` не переносится, выводится с отступом и вертикальной чертой слева, отделён пустыми строками.

### 13.3. Режим ASCII

С флагом `--ascii` замены: `🪙` → `coins`, `★` → `*`, `☆` → `.`, `✔` → `[OK]`, `✘` → `[X]`, `◐` → `[~]`, `•` → `-`, `·` → `|`, вертикальная черта блока кода → `|`.

```
jquiz/

│   ├── selection.py     # веса, recency, выбор вопросов
│   ├── economy.py       # монетки, стрик, дневной бонус, применение исходов
│   ├── shop.py          # каталог, покупки, титулы, пользовательские награды
│   ├── storage.py       # progress.json и config.json, атомарная запись

Модули `checking`, `selection`, `economy`, `shop`, `bank` не выполняют ввод-вывод и не обращаются к системным часам и глобальному `random` напрямую. Время и генератор случайных чисел передаются параметрами. `session` получает объект ввода-вывода, который в тестах подменяется заготовленными ответами.

## 15. Критерии приёмки

1. `jquiz play` проводит сессию из 10 вопросов, все четыре типа корректно отображаются и проверяются.
2. Для `short` ответ ` HashSet; ` засчитывается при эталоне `hashset`, ответ `strip()` засчитывается при эталоне `strip`.
3. Для `output` ответ `True` не засчитывается при эталоне `true`.
4. Нечисловой ввод или номер вне диапазона в `choice` приводит к повторному запросу и не меняет прогресс.
5. Веса меняются по таблице 8.1 и не выходят за границы 0.25–16.
6. При фиксированном seed и 10 000 выборах одного вопроса из пула двух вопросов с одинаковым `recency` и весами 8 и 1 отношение частот лежит в диапазоне 6–10.
7. Вопрос, показанный меньше суток назад, выбирается реже такого же по весу вопроса, показанного 7 дней назад (проверяется тем же способом, ожидаемое отношение около 4).
8. Монетки, стрик и дневной бонус работают по разделу 9 и переживают перезапуск программы. Смена даты сбрасывает дневной счётчик.
9. Покупка списывает монетки, расходник появляется в инвентаре и работает во время вопроса. Неприменимая подсказка не списывается.
10. Если убить процесс посреди сессии, все уже завершённые ответы учтены в `progress.json`, а файл корректен.
11. Повреждённый `progress.json` не роняет программу, копия сохраняется.
12. `jquiz validate` находит дубликаты `id`, отсутствующие обязательные поля, неверный индекс `answer` и многострочный `answer` у `output`.
13. `jquiz play --weak` при отсутствии слабых вопросов завершается с сообщением и кодом 0.
14. `jquiz stats` показывает корректную статистику по темам и топ слабых вопросов.
15. Юнит-тесты покрывают нормализацию ответов, валидацию банка, расчёт `recency`, обновление весов, выбор вопросов, начисление монеток, стрик, дневной бонус и покупки.
