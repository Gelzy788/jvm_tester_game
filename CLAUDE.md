# jquiz

CLI-тренажёр по Java Core. Полное ТЗ: docs/spec.md — источник истины.
Если код и ТЗ расходятся, прав ТЗ. Если ТЗ неясно — спроси, не додумывай.
План по этапам: docs/plan.md. Делай только текущий этап.

## Стек
Python 3.10+, только стандартная библиотека. pytest — только dev-зависимость.

## Архитектура (не нарушать)
- checking, selection, economy, shop, bank — чистые функции: без print/input,
  без файлов, без datetime.now() и без глобального random.
  Время (now: datetime) и rng: random.Random передаются параметрами.
- storage — единственный модуль, который читает и пишет файлы.
- ui — единственный модуль с print/input. session работает через объект IO
  (Protocol); в тестах его заменяет FakeIO с заготовленными ответами.
- cli — только разбор аргументов и вызов других модулей, без бизнес-логики.
- Типы вопросов обрабатываются через реестр (тип -> валидация, показ,
  проверка), а не через цепочки if по всему коду.
- Числа из ТЗ (цены, коэффициенты весов, пороги, бонусы) — константы в одном
  месте, без магических чисел.

## Правила работы
- Сначала тесты по ТЗ с комментарием-ссылкой (# spec 8.1), потом код.
- Никогда не меняй тест, чтобы он прошёл. Если считаешь тест неверным —
  остановись и объясни почему.
- После изменений `pytest -q` должен быть зелёным.
- Не добавляй ничего из раздела 4 ТЗ («Не входит в MVP»).

## Команды
- pip install -e ".[dev]"
- pytest -q
- python -m jquiz
